## 5. Ценность и ответственность

### 5.1 Влияние на принятие решений

Система **не принимает окончательных решений о контенте**. Она:
1. ставит атрибут «тип фронт-вокала» автоматически только при уверенности выше порога, рассчитанного под SLA;
2. передаёт остальные треки модератору с объяснением (голоса трёх модальностей, их согласие, уверенность, причина решения);
3. ведёт журнал всех решений, чтобы любую метку можно было проверить и отменить.

Метка влияет на фильтры поиска и рекомендации. Ошибка не вредит человеку напрямую, но ухудшает выдачу и может несправедливо понижать видимость отдельных исполнителей (п. 5.3).

### 5.2 Карточка модели (Model Card)

| Поле | Значение |
|---|---|
| Назначение | атрибут «тип фронт-вокала» (male / female / group / instrumental) для фильтров поиска и признаков рекомендаций в музыкальном каталоге |
| Не предназначена для | определения пола, возраста или идентичности исполнителя; модерации контента; юридически значимых решений |
| Вход | метаданные (исполнитель, альбом, название) + 10 с аудио |
| Модель | 3 логистические регрессии (TF-IDF текста, 120 статистик временного ряда, CLIP-эмбеддинг спектрограммы) + среднее вероятностей с **равными** весами (вариант поздней fusion, проверенный в ЛР3) + порог |
| Качество (MTAT test, исполнители вне обучения) | Macro-F1 0,748 (для сравнения: веса 0,1 / 0,4 / 0,5, подобранные по val в ЛР2, дают 0,723 — подбор весов по val переобучился); при SLA 10%: покрытие 44%, ошибка автометок 8,4% |
| Качество на другом каталоге (Jamendo) | Macro-F1 0,387 (2010–2017: 0,429); при пороге под SLA 10% ошибка 14,8% — **требуется перекалибровка** |
| Калибровка | ECE 0,176 на MTAT (среднее вероятностей недоуверенно), 0,049 на Jamendo; порог τ подбирается по val под SLA, поэтому калибровка учитывается через кривую «покрытие — ошибка» |
| Ресурсы | ≈ 0,08 с на трек, ≈ 50 ₽ на 1 млн треков (CPU) |
| Известные ограничения | слабые метки; жанровое смещение; класс group неоднороден; текст не переносится между каталогами |

### 5.3 Смещения и справедливость

1. **«Мужской / женский» — характеристика звучания, а не гендер исполнителя.** Высокие мужские голоса (контратенор), низкие женские, детские голоса и голоса трансгендерных и небинарных исполнителей система может размечать «неправильно» относительно самоидентификации. Поэтому в интерфейсе нужна формулировка «мужской / женский тембр вокала» и запрет использовать метку как атрибут человека.
2. **Жанровое смещение.** В обучающем каталоге мужской вокал сцеплен с роком, хор — с оперой и церковной музыкой. Для жанров, мало представленных в обучении (хип-хоп, этническая музыка), ожидается больше ошибок. Для них нужен мониторинг точности по жанрам.
3. **Смещение каталога.** Обучение на независимом лейбле 2000-х годов, поэтому на современном коммерческом поп-каталоге качество ниже (проверено на Jamendo).
4. **Эффект на исполнителей.** Ошибочная метка «инструментал» уберёт трек из подборок «с вокалом». Отсюда приоритет модерации для треков с несогласием модальностей.

### 5.4 Конфиденциальность и безопасность

- Персональные данные не обрабатываются: на вход идут метаданные произведения и аудио. Журнал решений не содержит данных пользователей.
- Аудио используется только для извлечения признаков (окно 10 с) и не сохраняется. Нужно соблюдать лицензию каталога: MTAT — только некоммерческое использование.
- **Атаки:** правообладатель может манипулировать названием трека (текстовая модальность), чтобы попасть в нужную подборку. Текст — лишь один из трёх голосов (в весах ЛР2 — 0,1), аудио-модальности его перевешивают; при несогласии модальностей трек уходит модератору.
- **Отказоустойчивость:** при пропуске модальности поздняя fusion теряет не больше 0,05 Macro-F1. При полной недоступности аудио трек уходит модератору (валидация).

### 5.5 Реестр рисков (по функциям NIST AI RMF: govern, map, measure, manage)

| Риск | Вероятность / влияние | Измерение | Мера |
|---|---|---|---|
| Сдвиг каталога → рост ошибок | высокая / высокое (Jamendo: 15% ошибок при SLA 10%) | ошибка по проверенным модератором трекам; доля согласия модальностей | перекалибровка τ на новом каталоге; алерт при падении согласия ниже 30% |
| Недостаток бюджета модерации | средняя / среднее | доля треков с флагом «бюджет исчерпан» | метки с флагом риска не попадают в публичные фильтры до проверки |
| Ошибки по жанрам и группам исполнителей | средняя / среднее | точность по жанрам и регионам | стратифицированная проверка, ручная разметка редких жанров |
| Использование метки как атрибута человека | низкая / высокое | аудит использования API | ограничение назначения в документации и контракте API |
| Деградация после обновления моделей | средняя / среднее | регрессионный тест на фиксированном наборе | версионирование моделей, откат |

### 5.6 Границы применения

Система применима для **первичной разметки** большого каталога при наличии модератора и размеченной выборки для калибровки. Она неприменима:
- без перекалибровки на новом каталоге;
- для треков короче 5 секунд;
- для голосовой и разговорной аудиозаписи (подкасты, аудиокниги);
- для решений о людях.

## 6. Защита

**Формат:** презентация из 14 слайдов (`presentation/Презентация_ЛР5.pptx`), доклад 15–20 минут (текст — `presentation/Речь_ЛР5.docx`), затем вопросы до 10 минут.

**Демонстрационный сценарий** (≈ 3 минуты внутри доклада):
1. Запуск: `python src/demo.py`. Система загружает модели и обрабатывает поток из 8 треков: 6 с теста MTAT, 2 из Jamendo.
2. Разбор трёх решений по журналу `results/demo_log.jsonl`:
   - «St. Eliyah Childrens Choir» — единогласие трёх модальностей, уверенная автометка «group»;
   - «Processor — Insomnia» — ошибочная автометка при пороге 0,425; показать, что при пороге под SLA 10% (0,575) трек ушёл бы модератору;
   - трек Jamendo «Flowers…» — несогласие модальностей → модератор + предупреждение.
3. Кривая «покрытие — ошибка»: выбор порога под SLA и почему на новом каталоге нужна перекалибровка.
4. Резервный план, если демо не запустится: заранее сохранённый журнал `demo_log.jsonl` и таблица из раздела 4.6.
