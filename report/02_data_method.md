### 3.2 Поток предобработки

```
метаданные трека ──► текст "исполнитель | альбом | название" ──► TF-IDF (символьные 2–5 + слова 1–2) ──► эксперт «текст»
аудио ──► валидация (≥ 5 с, не тишина) ──► 16 кГц (гармонизация каталогов) ──► 22,05 кГц, окно 10 с
          ├─► 20 покадровых признаков × 20 шагов по 0,5 с ──► 120 статистик ──► эксперт «временной ряд»
          └─► лог-мел спектрограмма (128 полос, 0–8 кГц) ──► PNG ──► CLIP ViT-B/32 ──► эксперт «спектрограмма»
три вероятности ──► среднее ──► контроллер: τ, бюджет, согласие ──► автометка / модератор + журнал + объяснение
```

Все энкодеры (TF-IDF, нормировки, SVD) обучаются **только на train**. Для обучения маршрутизации используются out-of-fold вероятности (GroupKFold по исполнителям).

### 3.3 Итоговая архитектура и интерфейсы

| № | Модуль (требование задания → тема ВКР) | Вход → выход | Решение по результатам ЛР | Обоснование |
|---|---|---|---|---|
| 1 | Сбор и валидация данных | метаданные + mp3 → проверенный объект, флаги проблем | валидация длительности и тишины, гармонизация 16 кГц, разбиение по исполнителям | ЛР1 (утечки), ЛР2 (правило S4) |
| 2 | LLM-модуль | спектрограмма → JSON {label, confidence} | **исключён из контура решений**, интерфейс сохранён | ЛР1: VLM 0,10–0,24 Macro-F1, уверенность не калибрована |
| 3 | Мультимодальный модуль | текст, ряд, изображение → вероятности 3 экспертов | три логистические регрессии + среднее вероятностей с равными весами (поздняя fusion); Macro-F1 0,748 на MTAT test | ЛР2: значимый прирост на MTAT, устойчивость к пропуску модальности; ЛР3: правило «равные веса» проверено как контроллер |
| 4 | Многоагентный модуль (распределение решений) | вероятности → автометка / модератор | **централизованное правило** «равные веса + τ»; MARL — экспериментальная ветка | ЛР3: правило 8,58 против MAPPO 2,79 |
| 5 | Контроллер риска, журнал, объяснение | решение → JSON-журнал, объяснение модератору | бюджет модерации, порог под SLA по кривой «покрытие — ошибка», предупреждение о несогласии модальностей | ЛР3, ЛР5 |
| — | Оптимизация обучения | — | Adam для нейросетевых вариантов слияния, Nesterov + wd 10⁻³ для одномодальной BiGRU | ЛР4: лучший оптимизатор зависит от архитектуры |

Реализация — `src/pipeline.py` (класс `VocalLabeler`), демо — `src/demo.py`.

### 3.4 Baseline, протокол, метрики

| ЛР | Baseline | Протокол | Основная метрика | Подтверждающие |
|---|---|---|---|---|
| 1 | LogReg на мел / MFCC | 200 клипов (50 на класс) + 1 009 полный тест; один промпт, JSON, temperature 0 | Macro-F1 | F1 по классам, MCC, доля невалидных ответов, ECE, latency, $ / 1000 |
| 2 | 3 одномодальные модели | test 1 009, блочный bootstrap по исполнителям, permutation test прироста | Macro-F1 | MCC, AUROC, Brier, ECE, пропуск модальности, latency, ₽ / 1 млн |
| 3 | «Равные веса + порог», одноагентный PPO | 1,92 млн переходов, 5 seed, 256 общих эпизодов | ценность разметки | Sharpe, CVaR, просадка, нарушения, вклад агентов |
| 4 | SGD | 2 400 шагов, одинаковый подбор lr, 10 seed | test Macro-F1 | шаги до цели, ECE, время, память, разложение дисперсии |

### 3.6 Угрозы валидности

| Тип | Угроза | Мера / статус |
|---|---|---|
| Внутренняя | утечка между частями (исполнители, сегменты трека, почти-дубликаты) | разбиение по исполнителям, удаление почти-дубликатов, OOF-вероятности; **контролируется** |
| Внутренняя | подбор гиперпараметров по тесту | только val; правило расширения сетки одинаково для всех; **контролируется** |
| Внутренняя | гипотезы ЛР2 сформулированы после первых результатов | честно отмечено; основные выводы подтверждены на отдельном наборе (Jamendo) |
| Конструктная | «мужской / женский» — тембр голоса, а не гендер исполнителя; class group неоднороден | оговорено в разделе 5; метка описывает звучание |
| Конструктная | метки слабые (теги, описания) | ограничение; ручная проверка подвыборки — будущая работа |
| Статистическая | в тесте 33 исполнителя → ДИ ±0,1 | блочный bootstrap, парные тесты, 5–10 seed |
| Внешняя | один основной каталог (Magnatune), смещение по жанрам; Jamendo — 281 трек | перенос проверен, прирост **не переносится**; нужна валидация на реальном каталоге |
